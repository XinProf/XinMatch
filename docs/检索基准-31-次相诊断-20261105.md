# 3-1 次相失败诊断：预筛召回为主，FoM 罚分弥散（2026-11-05）

> 触发：基准报告 §9.4-1「`3-1` 这一类『次相在候选池内但排不上去』→ FoM 层排查」。
> 方法：`tools/_probe_31_fom.py`（只读探针：名额扫描 + 罚分分解 + 单判据反事实，
> 不改引擎、不改权重）。
> **结论先行：默认名额下 `3-1` 的次相根本不在候选池内 —— 主因是预筛召回，不是
> FoM 排序。§9.3「在候选池内也排不进 Top-20 族」只在 8000 深名额下成立，且罚分
> 是弥散的（三项各 +0.05~0.08），属「次相稀释」形态，不是某个判据的 bug。**

## 1. 层级定位（名额扫描）

样品 `3-1`（ZnO 主相 + Al₂O₃ + CaF₂，208 峰，auto_process 流水线）：

| 预筛名额 | 池 / 族 | Al₂O₃ 最佳卡 | CaF₂ 最佳卡 |
|---|---|---|---|
| **1000（生产默认）** | 1000 / 581 | **不在池内** | **不在池内** |
| 8000 | 8000 / 5313 | `96-110-1168` entry 577 / **族 420** | `96-155-9793` entry 426 / **族 303** |

- 指定卡：Al₂O₃ = `96-230-0448`、CaF₂ = `96-230-0449`（与 3-2/4-1 同系列样品一致）。
- 注意复现口径：§10.1 的 8000 实验是直接调 `prescreen(candidate_limit=...)`；
  `search_match` 的 `recall_max_candidates` 是 v2 旋钮、**不转发给 v3**，复现要用
  `search_match_v3(candidate_limit=8000)`。

## 2. 罚分分解（8000 池，对照榜首 ZnO fom 0.7728）

`compute_fom` 为罚分制：`1 − Σ w·(1−p) − w_iscale·|ln f|`。

| 相 | 最佳卡 | fom | 最大压制项 | 相对榜首罚分差 |
|---|---|---:|---|---|
| Al₂O₃ | `96-110-1168` | 0.5851 | **intensity** | +0.063（ncorr +0.060、peakpos +0.058 紧随） |
| CaF₂ | `96-155-9793` | 0.5934 | **ncorr** | +0.077（peakpos +0.056） |

- 指定卡 `96-230-0448`（刚玉）**intensity=0.000** —— 相对强度形与实测完全对不上。
- 两个次相的罚分差**没有单项独大**：intensity / ncorr / peakpos 各 +0.05~0.08。
  这是「次相稀释」的典型形态：次相的线大多被主相掩盖或重叠，`ncorr`（自身反射
  解释率）与强度一致性天然低 —— 不是某个判据算错。

## 3. 单判据反事实（纯算术，把压制项换成榜首值重算 FoM）

| 相 | 反事实 | fom | 卡排名 | 族排名 |
|---|---|---:|---:|---:|
| Al₂O₃ | intensity → 0.941 | 0.6480 | 26 / 8000 | **18 / 5313** |
| CaF₂ | ncorr → 0.900 | 0.6700 | 14 / 8000 | **6 / 5313** |

含义：距 Top-20 族只差 **0.06~0.08 的 fom**；任何单项判据的「次相友好化」都足以
把它们拉进 Top-20。但 §11.2 已证：任何单一覆盖类指标都会**同时**抬高另一类假密集卡
—— 本池 Top-12 里 `As19 Eu6 Rh30`、`F12 H21 K3 Mn6 Na8` 这类多线杂卡就是那
「另一类」。这与 §11.4 的结论（任何单一覆盖指标都会同时抬高另一类假卡）互相印证。

## 4. 结论与下一步

| 结论 | 含义 |
|---|---|
| `3-1` 主因 = **预筛召回**（默认名额下不在池内） | §9.4-1 的「FoM 层」定性需修正为「预筛层为主、FoM 层为次」。预筛侧救回 `3-1` 需要给多相样品的次相更多/更聪明的名额 —— **§10.5 的相位族配额正是这条路** |
| FoM 层非 bug，是次相稀释 | 与 §11.4「剩余失败 = 召回 + 稀释」一致；**不动冻结权重** |
| 若未来动 FoM | 必须同时跑合成 `synthetic_v3` + 真实 `txt` 双基准（§11.5 的教训：合成尺子会系统性高估强度形类规则） |

### 附带发现（独立缺陷，**3.4.1 已修**）

库里 **416 / 78,035 条 `formula` 为 NULL/空**。`same_phase` → `_composition_agrees`
对「无化学式证据」返回 `True`（"no evidence, not a mismatch"）→ **NULL 式卡可假匹配
任何真值、折入任何相位族**。本次未污染基准数字（`3-1` 的 NULL 卡在 rank 800，
不在 Top-20），但属潜在正确性风险（真值匹配虚高 / GUI 折叠错族）。

**已按方向 1 落实（3.4.1）**：`_composition_agrees` 改为「两侧都非空才可能为真」，
晶胞路径不变。真实谱基准随之下降 **卡级 24→19、族级 27→19、序贯完整 5→4**，
逐条归因见 `docs/基准报告-物相检索-v3.md` §13.4（`7-1` 一张空白卡命中 7 个真值、
`5-3` 两个空白族代表 + 轮 3 空白羟基磷灰石卡）。合成基准逐字节不变。
探针里原先的 `c.entry.formula and` 手工过滤已删除，语义由 `same_phase` 本身保证。

**仍待做（方向 2）**：这 416 条都带晶胞与峰，是真结构缺 `_chemical_formula_sum`。
用 `elements_from_sites` 合成 `formula` 回写（不碰峰，可等价补丁）能把下界抬回真实水平。
