# 检索基准自查：为什么 synth_12 在 v3 库上失败（2026-11-04）

> 触发：v3.1.0 收尾后，用重建版 `COD-Inorg-20261020.xinDB`（78,035 相）重跑序贯鉴定，
> synth_12 从文档记录的 2/2 退化为 1/2 —— MgO 被 `96-100-8598 H0.95 Ni Ti` 顶掉。
> 本文是这次的定位过程与结论。**结论：不是引擎缺陷，是基准尺子（合成谱）与新库口径不再自洽。**

## 1. 现象

`SequentialIdentifier` + `search_residual` 每轮自动取 Top-1，库 = `COD-Inorg-20261020.xinDB`：

| 样品 | 真相相 | 第 1 轮 | 第 2 轮 | 覆盖 | 判定 |
|---|---|---|---|---|---|
| synth_02 | SiO₂ + CaCO₃ | SiO₂ 0.813 | CaCO₃ 0.914 | 93.5% | 2/2 ✓ |
| synth_04 | Fe₂O₃ + SiO₂ | Fe₂O₃ 0.729 | SiO₂ 0.857 | 79.8% | 2/2 ✓ |
| synth_12 | MgO + MgAl₂O₄ | MgAl₂O₄ 0.768 | **H0.95NiTi 0.702** | 80.1% | **1/2 ✗** |

## 2. 排除项（都不是原因）

| 怀疑 | 检验 | 结果 |
|---|---|---|
| 候选生成漏掉真相相 | `reader.prescreen()` 直接看候选集 | **MgO 在候选集里**（96-900-6471～6480 共 20 条），800 条上限未挤掉它 |
| 残差被"已确认相未扣净的强线"污染 | 对比原始谱与残差在 58.38°/64.14° 的强度 | 已扣净（原始 23577/39853 → 残差不出现在 Top-12），**无污染** |
| 弱噪声峰稀释分母 | 打分前剔除 <1% 最强峰的峰（41→39） | 无效，排序不变 |
| `npeaks`/`ncorr` 按条数计分 | 改按强度加权重算 | MgO 0.663→0.795，但新的假相也升到 0.80，**不能定案** |

## 3. 真正原因：`intensity` 判据被"换卡的强度"砸掉

同一个条目在两代库里强度不同：

| 条目 | 来源 | 反射数 | 最强 4 线 (2θ/I) | 220/200 比 |
|---|---|---:|---|---|
| `96-900-6475` MgO | **v2 SQLite**（合成谱生成用） | 7 | 41.25/1000, 59.75/**284**, 75.19/127, 89.57/76 | 0.28 |
| `96-900-6475` MgO | **v3 重建库**（检索用） | 11 | 41.25/1000, 59.75/**570**, 75.19/171, 89.57/76 | 0.57 |

实测残差（合成谱）：41.24/50000、59.74/**14590**（=0.29×最强线）——**与 v2 卡完全一致，与 v3 卡差一倍**。

于是 MgO 的五项判据变成：

```
96-900-6475 Mg O : peakpos 0.9971（几乎满分） intensity 0.2647（被腰斩） npeaks 0.1463  ncorr 0.5455  i_scale 0.8807 → FoM 0.6626
96-100-8598 H0.95NiTi：peakpos 0.830  intensity 0.8737  npeaks 0.2927  ncorr 0.2927  i_scale 1.0064 → FoM 0.7024
```

位置精度 0.9971 vs 0.830 的巨大优势，被 `intensity` 一项（权重 0.1112）抵消掉 0.068，
再叠加 `npeaks`（假相 150 条线撞中 12 个弱峰，权重 0.2306）就反超了。

## 4. 强度为什么会变

v3 重建库的强度口径已调整到更接近物理值（含 LP/结构因子修正的正常化），
v2 卡则是未修正的 I_calc。交叉验证：Quartz `96-500-0035` 在 v3 里
4.25/198 对 3.34/1000 = **19.8%**，教科书 (100)/(101) ≈ 22%，吻合。

这与 T0.8 结论 2（"CIF 强度惯例差异真实存在，但当时不做全局 LP 修正，因为合成谱基线绑定旧惯例"）
是同一件事的后续 —— **v3 重建时把强度口径改了，但 13 组合成谱仍是用 v2 卡强度生成的**，
两边不再自洽。

## 5. 结论与动作

| 结论 | 影响 |
|---|---|
| synth_12 的失败**不能**用来评价引擎 | 尺子与库不同源 |
| 13 组合成谱（`D:\Project\XRD\test_xrd\synthetic`）**全部需要按 v3 库重建** | 强度来源改为 v3 库同一条目 |
| 整谱 Top-10 被 beryl 族 30+ 变体占满、方解石 Top-60 不见（单体 0.7723 vs 榜首 0.7740，差 0.0017） | 独立问题：**候选近重复聚簇**，与打分无关 |
| "密集卡凭条数霸榜" | T0.8 已证权重路线关闭；只在序贯场景做局部反制，不动整谱冻结口径 |

**下一步顺序**：先用 v3 库重建合成谱基准 → 在自洽基准上重测 → 再判断是否真要动引擎。
不要拿一把与库不同源的尺子去校准算法。

## 6. 复现

```bash
# 序贯多相（v3 库）
python - <<'PY'
from pathlib import Path
from xinmatch.core.io import load_pattern
from xinmatch.core.peak.peak_search import find_peaks
from xinmatch.core.db.reader_v3 import XinDBReader
from xinmatch.core.search.sequential import SequentialIdentifier, search_residual
r = XinDBReader(Path(r"D:\Project\XRD\XinMatch-DataBase\data\COD-Inorg-20261020.xinDB"))
for name in ("synth_02", "synth_04", "synth_12"):
    p = load_pattern(Path(r"D:\Project\XRD\test_xrd\synthetic") / f"{name}.txt")
    seq = SequentialIdentifier(find_peaks(p.two_theta, p.intensity), wavelength=p.wavelength)
    out = [name]
    for _ in range(2):
        res = search_residual(seq, r, top_n=10)
        sel = seq.select(res.candidates[0])
        out.append(f"{res.candidates[0].entry.formula}({res.candidates[0].fom:.3f}) {sel.covered_fraction:.1%}")
    print(" | ".join(out))
r.close()
PY
```
