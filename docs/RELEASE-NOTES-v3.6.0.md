## XinMatch v3.6.0 — GUI 从骨架到可用、峰位精修提速两个数量级

> 基线 `v3.5.0`（tag `fe4ccfe`）｜本次是**功能补齐 + 性能 + 基准体系**版本。
> `.xinDB` 格式、FoM 权重、P 值定义、检索默认行为**逐项不变** —— 本轮所有
> A/B 的结论都是「不动」（见 §四末两行），三把尺子上的已发布数字继续有效。

### 一、要解决的问题

三件事，前两件是「界面点了没反应」，第三件是「明明算得完却在等 IO」。

1. **15 个功能模块里有 11 个菜单动作是空的。** 工具栏与「分析」菜单里
   「定量分析」「微结构分析」「指标化」「数据导出」都能点，点了只在状态栏
   播一句「模块骨架已就位」。core 侧能力其实早已 ✅（`core.quant` / `core.micro`
   / `core.index`，T8 / T11 / T9 全部完成），只是没人把 GUI 接上去。
2. **候选列表只显示 20 行，用户看不到已经算出来的答案。** 打分对全池算完，
   `top_n` 只是切片 —— 20 行时族级覆盖 81/98，抬到 50 行是 89/98，而计算成本
   为零。这件事卡在「显示预算是产品决策还是算法参数」没定。
3. **预处理比检索本体慢一个数量级。** 实测默认库端到端 2.31 s 里 1.32 s 是
   导入、0.37 s 打分、**检索本体 0.18 s**；而 207 峰的 `3-1.txt` 光预处理就
   35.2 s（峰位精修用 Nelder-Mead，逐峰重启）。

### 二、核心能力

| 能力 | 说明 |
|---|---|
| **Profile Fitting 对话框** | F5 同一入口；谱形四选一（pseudo-Voigt 默认 / Gaussian / Lorentzian / Pearson VII），结果表给精修 2θ / FWHM / 面积 / I-I₀ + Rwp，拟合曲线叠加进谱图区，「应用到峰列表」写回后可重新 Search-Match |
| **RIR 定量分析对话框** | 已确认物相 + 峰列表 → 主峰强度取 `Phase.correlations` 指向实验峰的最大积分强度；RIR 列可编辑（默认 1.0）；计算委托 `core.quant.rir_quantify`（Hill–Howard 绝热法）；wt% 写回 `Phase.weight_fraction` 并刷新匹配列表 |
| **微结构分析（Scherrer / W-H）** | 两页共用 λ 与 K：Scherrer 逐峰 D + 算术平均；Williamson-Hall 报 D / ε / R² / 参与峰数并列出回归数据。两页互不阻断（单峰时 W-H 只提示）。**本版不做仪器宽化校正**，界面常显提示 |
| **指标化向导（Treor90 / DicVol06）** | d 由 2θ + λ 换算、跳过已排除峰；算法 / 波长 / 容差 / 7 个晶体系统可选（默认高对称四系）；`deduplicate` + `rank_solutions` 后 10 列结果表；空解只提示不弹框；选中行复制单胞 |
| **数据导出聚合菜单** | 谱图 ASCII profile / 两列 2θ–I、峰列表 CSV、候选列表 CSV（与界面显示同源）、匹配列表 CSV、`.xinm`、所选相 CIF；三张表的右键「导出 (CSV)…」此前悬空，现已接线 |
| **菜单动作全部接通** | 数据导入 / 原始数据处理（背景·平滑·Kα2·重置 子菜单）/ 峰列表 / 限制条件 / Rietveld 精修 / 上述五个 —— 只剩 `user_db` 仍占位（无 core 能力，需求待定） |
| **候选列表行数上限** | 设置项 `candidate_list.max_display_rows`（默认 50，按族计）；表格折叠时截前 N 行、展开时按卡；`.xinm` 存档与 `win._candidates` 保持全量；报告改用 `visible_results()` 与表格同源 |
| **峰位精修改用 LM** | `scipy.optimize.least_squares` 替代 Nelder-Mead 逐峰重启：预处理 **35.2 s → 0.35 s**，207 峰 CLI 端到端 **36 s → 2.3 s** |
| **元素周期表重设计** | 尺寸改由字体度量驱动（不再被全局 QSS 的 `padding` / `min-height` 裁字）；三态用「颜色 + 线型 + 字重」三重编码（红绿色盲友好）+ 常显图例 + 逐键 tooltip；弹窗尺寸自适应 + 滚动兜底 |
| **样品元素一行录入** | 「限制条件」页填 `Zn Al Ca O F` → 其余元素自动标排除（走 `element_inv` 倒排），真实谱相召回 **20/43 → 30/43**，`3-1` 次相 1/3 → 3/3 |

### 三、关键设计决定（以及为什么）

1. **GUI 只做接线，不重写算法。** 五个新对话框的计算全部委托 `core.*`
   （`fit_profile` / `rir_quantify` / `scherrer_from_peaks` / `williamson_hall_from_peaks`
   / `index_treor`·`index_dicvol`），GUI 侧只做参数采集、结果呈现、空数据守卫。
   这样 CLI 将来复用同一套语义，不会出现「GUI 一套、CLI 另一套」。
2. **指标化不做「首行即答案」的暗示。** 合成立方 a=4.0 Å 的谱上，DicVol 首位
   正确给出 `cubic a=4.0000`，但 **Treor 首位是 `tetragonal a=2.0 / c=2.3094`**
   —— 同 FoM（6.00）、同样 6/6 全指标化，按 `rank_solutions` 的「同 FoM 体积小
   优先」规则（Werner 1985）四方胞 V=9.24 排在立方胞 V=64 之前。这是文献规则
   不是 bug，所以界面**常显提示**「等效低对称胞可能排在真对称之前，别只看第一行」，
   测试也断言「存在 cubic a≈4.0」而不是「首行 cubic」。
3. **微结构结果不回写峰列表。** 与参考软件一致：Scherrer / W-H 产出的是结论
   数值，不是峰的改动作业；回写只会让用户误以为峰被重拟合过。
4. **RIR 的 RIR 列默认 1.0 但可编辑。** 参考软件同样由用户按 PDF 卡片填 I/Ic
   —— 库内没有可靠的 RIR 字段，默认硬编码一个「标准值」比留空更危险。
5. **周期表尺寸不写死。** 见 §五之一，写死 38×30 在主题 QSS 下内容区只剩 8 px。
6. **候选列表上限走设置项而不是常量。** `tests/ui/*` 的夹具库很小，如果写死
   常量会让三处检索固定取 200 卡、测试变慢；走 YAML 设置后测试可钳位，用户也能改。

### 五、升级注意

1. **周期表的样式问题不是「字体太小」。** 如果你之前觉得元素符号被裁，
   根因是主题 QSS 的 `padding: 5px 14px` 吃掉了按钮内容区、且 `min-height: 20px`
   优先级高于 `setFixedSize()`。现在尺寸由 `QFontMetrics` 计算，9 / 13 / 16 pt
   三档都验证过 `min == max == actual`。
2. **候选列表默认显示 50 行**（原 20 行）。觉得太长可以在
   「设置 → 选项 → 候选列表行数上限」调回去；这只是显示截断，不影响检索本身。
3. **`.xinm` 存档仍是全量候选**，不因显示截断而丢失数据。
4. **`.xinDB` 参考库格式未变**，旧库直接沿用，无需重建。
5. **配置文件新增一个键** `candidate_list.max_display_rows`（缺失时按 50 处理，
   旧配置可直接用）。
