## XinMatch v3.6.1 — 三处实测报障修复（图例重复 / 精修卡死 / 晶系误判）

> 基线 `v3.6.0`（源码 `489e71d`）｜本版是**纯缺陷修复**版本，无新功能、无接口变更、
> 无数据格式变更。`.xinDB` schema、FoM 权重、检索默认行为、`core.*` 公开签名
> **逐项不变**，基准数字与 v3.6.0 完全一致。
>
> v3.6.0 的安装包虽已构建，但**人工验收未进行、未打 tag、未发布**；本版直接取代它，
> 用户不需要先装 3.6.0 再升级。

### 一、要解决的问题

三处都是真实使用中撞到的，**根因互不相同**，不是同一个 bug 的三种表现。

1. **「选中一个物相，它在图上标出两个；确认两个物相，图上给了四个；连试样都给了两个。」**
   图例里每条曲线出现两次，用户据此以为重复绘制、甚至以为确认动作加了两次相。
2. **「打开精修向导是空的；按下一步、下一步，结果就卡死。」**
   窗口整块白屏 + 标题栏出现「(未响应)」，只能强杀进程。
3. **「匹配列表里六方相显示成单斜。」**（截图里 `Anatase` / `Rutile` 的晶系列是 `T`，
   但同一列的其他样品出现 `M`，而库里那几条是六方。）

### 二、修了什么

#### ① 图例重复 —— 曲线一直只有 1 条

| 项 | 内容 |
|---|---|
| 实测指纹 | `plotDataItems = 1` 但 `legend_rows = 2`（曲线对、图例错） |
| 根因 | pyqtgraph 0.13.7 的 `PlotItem.addItem()` 末尾会自己把带 `name` 的 `PlotDataItem` 加进 legend（`PlotItem.py:516-552`：`if name is not None and self.legend is not None: self.legend.addItem(item, name=name)`，`name` 取自 `item.name()`）；`pattern_view` 又手动 `self._legend.addItem(...)` 一次 |
| 修复 | 删掉 `add_pattern` / `add_stick_pattern` 里的手动加图例 |
| 连带修复 | `remove_pattern` / `remove_stick_pattern` 不再按**名字**删图例行。`PlotItem.removeItem()` 已按 **item 身份**移除（`LegendItem.removeItem` 匹配 `sample.item is item`）；按名字删会误删同名兄弟曲线那一行（同一相重画时必然同名） |

**用户可见效果**：一条曲线一行图例。选 1 相 → 1 条实验 + 1 条参考线；确认 2 相 → 1 + 2。

#### ② 精修向导卡死 + 白屏 —— 一个阻塞，加一条误触路径

| 项 | 内容 |
|---|---|
| 卡死真因 | `_run_refinement()` 在 **GUI 线程同步**调 `_execute_driver()`（GSAS-II 子进程，几十秒到几分钟），只调一次 `QApplication.processEvents()` 就再无重绘机会 → 窗口进「(未响应)」→ DWM 丢弃窗口内容 → **白屏**。截图里的空白不是布局没建起来，是阻塞的后果 |
| 误触路径 | 导航条原为 `[上一步] … [下一步][开始精修][完成]`。第 4 页隐藏「下一步」后，「开始精修」**滑到同一位置**；用户在参数页连点两下「下一步」，第三下正好落在滑过来的「开始精修」上 → 直接启动长任务 |
| 修复 1 | 改走 `run_with_busy()`（`xinmatch/ui/busy.py`：后台 `QThread` + 模态走马灯 + 排队信号回 GUI 线程）；`processEvents()` 全部移除 |
| 修复 2 | 「▶ 开始精修」**移进第 4 页内部**，底部导航条只剩 `上一步 / 下一步 / 完成`，物理位置不再重叠 |
| 修复 3 | 新增 `_set_running()` / `_on_refine_done()` / `_on_refine_failed()`：运行期间锁住导航与重复提交；失败给可读文案（不再只 `traceback.print_exc()`）；异常后可直接重试 |
| 修复 4 | 未勾选任何相时拒绝启动（不把空相列表喂给 GSAS-II）；`phases` 为空时第 1 页显示明确空态 |
| 观感修复 | 结果图原先是 pyqtgraph 默认**黑底**（违反「浅色主题下谱图区严禁黑色」）→ 按 `theme.THEMES[current]["chart_bg"]` 上色；晶胞表原被 `QPlotWidget` 的 Expanding 策略挤成**只剩 1 行可见**（多相精修看起来像只精修了 1 个相）→ 改 3:2 高度分配 + 「相」列 Stretch / 数值列 ResizeToContents；`cell is None` 时不再整行空白（填 `—`） |

**实测验证**：真实 `exec()` 模态下让 driver 干 1.2 s，同时跑 100 ms `QTimer` 数滴答 ——
**36 次**（旧代码只剩 1~2 次），精修完成后结果正常回填、Rwp 正常显示。

#### ③ 晶系单字母 —— 六方被标成单斜

| 项 | 内容 |
|---|---|
| 根因 | `tables._crystal_system_letter()` 只按「非 90° 角个数」判低对称：`n_non90 == 1 → M`（单斜）、否则 `A`（三斜）。而六方（a=b、α=β=90°、γ=120°）**唯一的非直角就是 γ** → 返回 `M`。石墨 / ZnO / 石英等所有六方相在两处列表里都显示成单斜；菱方（a=b=c、α=β=γ≠90°）落到 `n_non90 == 3` → `A`（三斜） |
| 修复 | 补两条几何判据：六方 `H`（a=b, α=β=90°, γ=120°）、菱方 `R`（a=b=c, α=β=γ≠90°），置于单斜/三斜判定**之前** |
| 字母表 | `C` 立方 / `H` 六方 / `T` 四方 / `R` 菱方（三方）/ `O` 正交 / `M` 单斜 / `A` 三斜；未知晶胞仍为 `X` |

### 四、关键设计决定

1. **修卡死用 `run_with_busy` 而不是自建 `QThread`。** 项目里已有统一入口
   （后台线程 + 模态走马灯 + `parent._busy_active` 重入保护 + 取消谓词），
   自建线程会绕过重入保护和取消上报，将来每个对话框一套写法。
2. **「开始精修」不留在导航条。** 也可以让它常显但禁用，但那只解决「误触」，
   没解决「用户以为这一页还是过渡页」的语义问题。放进页面内部后，
   导航条只负责导航，页面内只负责该页动作。
3. **不做「进入第 4 页就自动开始精修」。** 精修可能跑几分钟，自动开始等于把
   一个昂贵动作绑定在一次翻页上；用户想先看看参数、改改背景阶数都做不到。
4. **晶系仍然由晶胞几何推导，不改成读 `entries.crystal_system`。** 后者确实在库里
   （`reader_v3.fetch_meta` 已带出），但 `Entry` 模型没有这个字段，为它加字段会
   牵动模型层与所有构造点；几何派生在「晶胞可信」的前提下是等价且零成本的。
   真正的教训是**上位规则推导必须显式枚举所有分支**，而不是等它自己 fallback。

### 五、升级注意

- **无数据迁移**。`.xinDB` 库、`.xinm` 存档、`config.yaml` 全部兼容，无需重建参考库。
- **无 API 变更**。`core.*` 公开签名未动；`RefinementWizard` 构造参数未动，
  仅内部按钮归属与运行线程改变（`driver` 注入的测试替身签名不变）。
- **图例行为变化**：如果外部脚本直接读 `pattern_view._legend.items`，行数会从
  「2×曲线数」变成「曲线数」—— 那是修复，不是回归。
